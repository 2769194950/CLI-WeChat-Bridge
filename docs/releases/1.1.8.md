# Version 1.1.8

**Release Date:** September 18, 2026

## Overview

Version 1.1.8 brings remote model and plan controls to all four CLI adapters, fixes cross-conversation reply routing on the WeCom channel, and aligns the bridge with Codex CLI 0.155 and Pi 0.85 runtimes. It also hardens daemon shutdown, adds a scheduled CLI compatibility gate, and repairs CI dependency installation. 74 files changed with 8,849 insertions and 292 deletions.

## Model and Plan Controls for Every Adapter

`/model` and `/model <number>` now work across Codex, Claude Code, OpenCode, and Pi in both standalone bridges and daemon slots, with numeric snapshots bound to the sender, process, workspace, and active session (valid for 5 minutes).

- **Codex** lists and switches models through the app-server model and thread settings APIs; `/plan` and `/plan off` switch the collaboration mode through the same connection.
- **Claude Code** drives the guarded native model selector and permission-mode footer at an idle prompt; local drafts, dialogs, and active turns cancel remote control instead of corrupting the terminal.
- **OpenCode** controls run entirely over authoritative server session APIs — no dependence on the visible TUI input box or menus — and every prompt is submitted with the committed agent, model, and variant.
- **Pi** lists scoped models (or the model registry when no scope is configured) through its native extension API and switches with `pi.setModel()`. Pi `/plan` stays extension-defined and is not exposed as a generic bridge command.

## Correct Conversation Routing

WeCom delivers messages from different conversations concurrently, while the bridge previously inferred reply targets from shared mutable state. Replies could cross over when a private chat and a group chat were active at the same time.

Inbound handlers now run with an async conversation context, synchronous replies are bound to the conversation that triggered them, and every asynchronous adapter event captures its target at enqueue time. Each adapter slot owns an atomic turn lease: a second dispatch while a turn is active receives a busy notice in its own conversation, failed dispatches roll back ownership, and late completion events can no longer clear a newer turn. Standalone bridges and the daemon share the same lease, rollback, and conditional cleanup helpers.

## Codex 0.155 Compatibility

The validated Codex range now spans 0.149 through 0.155. Codex 0.155 persists app-server threads lazily, which broke the previous startup path that pre-created a shared thread and resumed it in the visible client — the visible TUI died with `no rollout found` during bootstrap.

Visible Codex clients now always start a fresh session and the bridge follows the thread the TUI creates. Deliberate restores of already persisted threads remain available through explicit `--session-start-mode restore`, WeChat `/resume`, and reuse of a connected visible window. Parent-agent-owned Codex threads that cannot accept direct input are rejected during resume discovery.

## Pi Completion and Runtime Alignment

The Pi adapter now reports `task_complete` for every settled turn, including turns without a visible reply. Previously a finished Pi turn left ownership state behind, so every follow-up WeChat message was rejected with "Pi is still working" until the bridge restarted.

Pi 0.85 requires Node.js 22.19.0 or newer; direct launchers and the daemon now enforce this before starting the visible TUI.

## Daemon Shutdown and Startup Stability

The visible Codex supervisor exposes authenticated shutdown control, and its child process is stopped during adapter disposal. Ctrl+C aborts in-flight WeChat long polls and clears the daemon endpoint at shutdown start, so restarting no longer surfaces stale endpoint warnings. The daemon and visible Codex client no longer race to create separate startup threads.

## CI and Maintenance

- A weekly CLI compatibility workflow installs the latest stable Codex, Claude Code, OpenCode, and Pi releases and verifies the capabilities the bridge depends on (Codex schema generation, Claude `--settings`, OpenCode server health, Pi extension flags).
- CI dependency installation is repaired by syncing `@xterm/headless` into `bun.lock`; frozen installs succeed again.
- Star History now refreshes weekly instead of every three days.
- The GitHub Pages product site received refreshed copy and motion design.

## Important Notes and Upgrade

The minimum Node.js version remains 22.13.0; using the Pi adapter requires 22.19.0 or newer. Upgrade the primary package with:

```bash
npm install -g cli-wechat-bridge@latest
```

Existing scoped-package users can upgrade with:

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

Restart running bridge, daemon, and visible CLI processes after upgrading. Codex visible clients will open a fresh session on first launch after the upgrade; use `/resume` from WeChat or `--session-start-mode restore` to continue a previous persisted thread.
