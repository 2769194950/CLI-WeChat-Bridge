# 版本 1.1.8

**发布日期：** 2026 年 9 月 18 日

## 概述

版本 1.1.8 将远程模型与计划模式控制扩展到全部四个 CLI 适配器，修复企业微信通道的跨会话回复路由，并对齐 Codex CLI 0.155 与 Pi 0.85 运行时。同时加固 daemon 退出流程，新增周期性 CLI 兼容性检查，并修复 CI 依赖安装。共 74 个文件变更，新增 8,849 行，删除 292 行。

## 全适配器模型与计划控制

`/model` 与 `/model <编号>` 现已在 standalone bridge 和 daemon 槽位中支持 Codex、Claude Code、OpenCode 和 Pi，编号快照绑定发送者、进程、工作区和当前会话，5 分钟内有效。

- **Codex** 通过 app-server 的模型与 thread 设置 API 列出并切换模型；`/plan` 与 `/plan off` 经同一连接切换 collaboration mode。
- **Claude Code** 在空闲原生提示符处驱动受保护的模型选择器与 permission mode；本地草稿、弹窗或活动任务会取消远程控制，不会破坏终端。
- **OpenCode** 的控制完全通过权威的 server session API 执行，不再依赖可见 TUI 的输入框或菜单；每条 prompt 显式携带已提交的 agent、model 和 variant。
- **Pi** 通过原生 extension API 列出 scoped models（未配置 scope 时使用 model registry），并用 `pi.setModel()` 切换。Pi `/plan` 仍由扩展定义，不作为通用 bridge 命令开放。

## 会话路由正确性修复

企业微信的不同 conversation 会并发投递消息，而 bridge 此前通过共享可变状态推断回复目标——私聊与群聊同时活跃时，回复可能串线。

入站处理现在运行在独立的 async conversation context 中，同步回复绑定触发它的 conversation，所有异步 adapter 事件在入队时捕获目标。每个适配器槽位持有原子 turn 租约：turn 进行中的第二次 dispatch 会在自己的 conversation 收到 busy 提示，失败的 dispatch 回滚占用状态，迟到的完成事件不会再清除新 turn。standalone bridge 与 daemon 共用同一套租约、回滚和条件清理逻辑。

## Codex 0.155 兼容

已验证的 Codex 范围扩展到 0.149 至 0.155。Codex 0.155 对 app-server 线程采用惰性落盘，破坏了此前「预建共享线程并在可见客户端中 resume」的启动路径——可见 TUI 在 bootstrap 阶段以 `no rollout found` 崩溃退出。

可见 Codex 客户端现在始终新建会话，由 bridge 跟随 TUI 创建的线程。恢复已落盘会话的途径仍然可用：显式 `--session-start-mode restore`、微信 `/resume`，以及复用已连接的可见窗口。恢复列表发现阶段会拒绝由父 agent 管理、无法接受直接输入的 Codex 线程。

## Pi 完成事件与运行时对齐

Pi 适配器现在为每个结束的 turn 报告 `task_complete`，包括没有可见回复的 turn。此前 Pi turn 结束后占用状态不会释放，后续每条微信消息都被拒绝为 "Pi is still working"，直到重启 bridge。

Pi 0.85 要求 Node.js 22.19.0 或更新版本；直接启动器和 daemon 会在打开可见 TUI 前强制检查。

## daemon 退出与启动稳定性

可见 Codex supervisor 增加带认证的退出控制，adapter 释放时会停止其子进程。Ctrl+C 会中止进行中的微信长轮询，并在退出开始时清理 daemon endpoint，重启不再出现 stale endpoint 提示。daemon 与可见 Codex 客户端不再竞相创建各自的启动线程。

## CI 与维护

- 新增每周 CLI 兼容性 workflow：安装最新稳定版 Codex、Claude Code、OpenCode 和 Pi，并验证 bridge 依赖的能力（Codex schema 生成、Claude `--settings`、OpenCode server 健康检查、Pi extension 标志）。
- 同步 `@xterm/headless` 到 `bun.lock`，修复 CI 依赖安装；冻结安装恢复正常。
- Star History 从每三天一次调整为每周一次。
- GitHub Pages 产品站点刷新了文案与动效设计。

## 重要说明与升级

Node.js 最低版本保持 22.13.0；使用 Pi 适配器需要 22.19.0 或更新版本。升级主包：

```bash
npm install -g cli-wechat-bridge@latest
```

已有的作用域包用户可以这样升级：

```bash
npm install -g @unlinearity/cli-wechat-bridge@latest
```

升级后请重启正在运行的 bridge、daemon 和可见 CLI 进程。升级后首次启动时，Codex 可见客户端将新建会话；需要继续之前的已落盘线程，可在微信发送 `/resume` 或使用 `--session-start-mode restore`。
